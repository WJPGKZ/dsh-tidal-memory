# 潮汐记忆 · dsh-tidal-memory

**让同一工作区的会话记住有用的事，并在需要时带着时间和出处回忆。**

潮汐记忆 **1.0.3** 面向 DeepSeek Harness `0.2.2-rc.5`。它把短期线索、正在进行的任务、经历和长期知识分层保存；同工作区会话共享普通记忆，可按稳定任务与显式场景追溯 L2 经历；私人日记目录只保留按日期命名的 Markdown，同日贡献合并为一份。按日自动汇总默认关闭；启用后只读取绑定工作区会话，并由指定主会话模型写入私人日记。

> **版本说明：**本文介绍已发布的 [1.0.3 版本](https://github.com/WJPGKZ/dsh-tidal-memory/releases/tag/v1.0.3)。1.0.3 更新发行包文档和版本标识，插件运行逻辑与 1.0.2 相同；已安装 1.0.2 的用户无需为此更新。安装请使用 Release 安装包；发布时的源码可查看 [`v1.0.3` 标签](https://github.com/WJPGKZ/dsh-tidal-memory/tree/v1.0.3)。

> **一个虚构例子：**在工作区的一次会话中说“记住：这个项目使用 pnpm”，之后在绑定同一空间的另一会话里询问包管理方式，插件可以从仍有效的记录中找回这一线索，并附上来源。实际结果受工作区绑定、记录状态、检索门槛和预算影响；并非每句对话都会被自动记住，也不保证每次都能召回。

## 能解决什么问题

- **跨会话延续上下文**：同一工作区共享记忆，不同工作区隔离。默认保存规则能识别的用户陈述和任务，不要求逐条审核；无法可靠理解的表达可能遗漏。
- **跨会话回忆任务经历**：可用稳定 L1 任务和显式加入的场景串联多个会话的 L2 经历；当前场景焦点只补充有界关联，不改变记录归属或把转述当作独立证据。
- **从长期记忆找到关联**：设置页提供可缩放、拖动的关系图和可筛选的分类列表。图谱可从 L2 经历或 L3 知识开始，查看来源、任务、场景、主题、标签和人工关联；孤立记录不会被强行连线。
- **用线索回忆，而不是把相似当事实**：标准组合使用词面、别名、时间和来源检索；可选本地 embedding 支持语义改写。图谱“可能相关”只是导航建议，不会自动合并事实或参与召回。
- **区分计划、回执和用户纠正**：明确的计划进入 L1，不算完成；文件工具回执只说明宿主报告的操作，不证明任务或产物已经完成。同一明确对象、明确旧值且无保护冲突的导出目录纠正会保留旧版本，有效期截至纠正时间；目录仍是用户陈述，不是产物位置验证。
- **淡忘但不擅自抹除**：记录有时间、状态和生命周期；默认不会因低激活而删除。可人工修正、归档或明确遗忘，遗忘会清理当前库中的相关派生数据。
- **私人内容与普通记忆分开**：每天只有一份 Markdown 正文；默认不向任何会话注入，用户可绑定一个同工作区主会话并精确限定模型路由。管理页只显示状态，不显示正文。
- **按名称选择主会话**：在“设置与迁移”展开相应用途即可按 DSH 侧栏名称搜索当前工作区的会话。未运行的会话也可选择；只在名称相同时显示辅助信息。选择器只请求目录及缓存的元数据，不启动会话、不为取标题读取聊天正文。各用途独立保存。
- **按需查证原始历史**：默认关闭；启用后只允许所选干净主会话、在精确匹配的 Provider/Model 路由下，查询用户明确指定的 1–3 个同工作区会话。只搜索普通用户/助手消息，最多返回 2 个上下文窗口、总计不超过 6 KiB；私人/继承会话与已遗忘来源会被排除，查证期间遗忘状态变化则整次不返回。结果不写入记忆。宿主接口可能先在内存中加载所选会话的完整快照；查证结果会进入当前主会话的模型请求。
- **旧历史补录**：不会自动扫描。管理页必须先选工作区会话并按词或日期预览，再逐条勾选确认；预览过期、来源变化、权限/遗忘状态变化或跨工作区时拒绝提交。补录只纳入可分类的用户原句，作为带来源锚点的 L1/L2 待核候选，不会自动提升为 L3 或合并进正在进行的任务。每批最多 200 条，超过上限须缩小范围；部分写入后可按原勾选重试。宿主读取接口仍可能先在内存中加载所选会话的完整快照。
- **按需使用模型整理**：深度整理可保持纯本地规则，也可选择工作区模型或单独配置 API；模型只接收有效普通 L1/L2，生成内容作为 L3 待核候选，不自动作为事实注入。L3 不设存储总量上限，注入预算只约束单次上下文。

## 快速开始

1. 升级前退出 DSH，备份共享数据根和各工作区已有的 `.tidal-memory`。不要仅复制正在使用的单个 SQLite 文件；首次安装可跳过此步。
2. 从 [1.0.3 Release](https://github.com/WJPGKZ/dsh-tidal-memory/releases/tag/v1.0.3) 下载一个 `standard`、`cpu` 或 `enhanced` 安装包，在兼容的桌面端通过插件安装流程安装并启用。三者使用同一插件 ID，**不要同时安装三份**。
3. 在页面**最上方选择 DSH 工作区**；这里显示 DSH 登记的名称，没有会话的工作区也在列表中。每个本地工作区用自己的 `.tidal-memory` 存四层记忆、日记和索引。要让新工作区的会话参与记忆，在设置页点击“绑定此工作区”；编辑中文别名仅影响下方设置卡片，不改工作区名称或目录。
4. 在“分层记忆”中添加一条合成测试记录，或在已绑定工作区说“记住：……”；新建另一个会话，在“回忆与整理”中检查结果，再决定是否导入旧资料。
5. 需要语义检索时，在“设置与迁移 → 高级设置 → 模型文件与下载”复制并手动运行对应安装命令，保存组合选择，再点击“准备本地语义索引”。标准组合不需要模型。

首次打开新版本时，旧 SQLite 私人正文、按年子目录及 `undated` 原件会整理为 `private\YYYY-MM-DD.md`；优先恢复原日期，同日合并且保留原始正文。确无原日期时明确标记为按导入日期归档，不伪造发生日期。SQLite 索引和写入暂存移到 `system\private`，不会再出现在正文目录。完成迁移前请保留升级前的数据根副本。

升级后，已运行的 DSH 需由用户重载插件或重启宿主，页面才会显示新版本。GitHub Release 安装包不等于已发布到 npm，也不代表已经在每个桌面环境中完成验收。

### 设置私人日记主会话

在“设置与迁移 → 此工作区的会话与权限”展开“私人日记主会话”，按名称选择，再保存该用途。模型由宿主的会话路由带出；路由缺失时先在 DSH 中为会话选择模型，再刷新。模型变动须重新确认，不能填入另一个模型代替。历史查证和大睡不继承私人日记授权。

**自动写日记需单独启用。** 在“全局 · 功能开关与模型来源”打开并保存“按日自动生成私人日记”，并为目标工作区授权主会话。宿主在空闲时读取绑定工作区内目标日期的用户与助手消息，由主会话模型生成 Markdown。也可在私人日记页显式选择单日回溯；已存在的自动日记不会重复追加。模型输入包含所选日期的工作区会话文本，因此会发送给所选模型；正文只写入私人日期文件，不进入普通记忆或管理界面。若不开启该选项，仍只有实际调用 `tidal_private_contribute` 或获准作者提交才会新增日记。

### 选择安装组合

| 组合 | 默认能力 | 本地模型 |
| --- | --- | --- |
| `standard` | 词面、别名、时间和来源检索；完整四层与图谱 | 不加载模型 |
| `cpu` | 上述能力加本地语义检索 | BGE-small-zh-v1.5，512 维，CPU；权重约 90.5 MiB |
| `enhanced` | 上述能力加本地语义检索 | Qwen3-Embedding-0.6B，1024 维；权重约 1.12 GiB，提供 Windows x64 Vulkan/CPU 引擎 |

三个包共用记忆结构，区别仅在初始语义组合；已经保存的设置优先于包默认值，也可以在设置页切换。模型和运行时不包含在插件包中，模型下载需要联网，但**记忆 embedding 在本机完成**。增强版指模型规模，不保证每个问题都优于 CPU 版。

设置页显示实际模型目录和带绝对路径的安装命令。也可在插件目录手动运行，先把占位内容替换为设置页显示的数据根：

```powershell
node scripts\setup-model.mjs --edition cpu --root '<数据根绝对路径>'
node scripts\setup-model.mjs --edition enhanced --root '<数据根绝对路径>'
```

安装脚本固定模型版本并校验权重与引擎 SHA-256；已安装包在加载时再次校验。下载来源为 [BGE ONNX 固定版本](https://huggingface.co/Xenova/bge-small-zh-v1.5/tree/75c43b069aac4d136ba6bc1122f995fedcfd2781) 和 [Qwen 官方 GGUF 固定版本](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B-GGUF/tree/370f27d7550e0def9b39c1f16d3fbaa13aa67728)。缺少模型或加载失败时会明确提示并降级到词面检索，不影响普通记忆保存。

## 设计：像回忆一样分层，但不冒充大脑

| 层 | 保存什么 | 默认处理 |
| --- | --- | --- |
| **L0 感知缓冲** | 短期用户会话线索 | 已处理的缓冲默认保留 72 小时；助手全文默认不捕获 |
| **L1 工作记忆** | 当前任务和待办 | 规则生成的任务默认 24 小时到期归档，可调整 |
| **L2 情景记忆** | 带时间、来源、任务或显式场景引用的经历、陈述 | 按线索召回；可沿同一任务/场景追溯跨会话经历；足够独立的重复证据才可经本地规则提炼 |
| **L3 长期知识** | 稳定偏好、约定和知识 | 不设记录总量上限；常驻、召回条数和预算只限制注入上下文 |

灵感来自分层记忆、遗忘和线索回忆，具体实现是可解释的本地规则和检索，并非真实神经网络模拟。每条普通记录区分用户陈述、观察、推断等性质，保留时间、版本和来源。**自动保存、常驻、相似度或人工关联都不等于事实已核实。**

日常整理默认使用本地规则。可选择“工作区会话模型”按已保存的 Provider / Model 路由整理，或配置 OpenAI-compatible API；调用前会先创建恢复点。模型只接收有效的普通 L1/L2，排除 L0 与私人日记；输出必须是符合结构的 JSON，且每条结果引用本批真实来源，原记录保留。引用存在不代表内容受来源支持，因此模型结果仅写入 L3 待核状态，确认前不参与普通召回；已有相同记录不会因模型转述而增加来源。API 密钥只支持 Windows 当前用户 DPAPI 保护，不回显、不放入普通配置或备份。外部模型服务的数据保留策略不由插件控制。

### 图谱如何使用

打开“记忆图谱”，默认查看当前有效的 L3，也可切换到 L2 追踪经历链。显式场景由会话通过服务创建并加入；场景关系只表示共同上下文，不证明经历内容相同。可以按层级、状态、主题或标签、关系类型和文字筛选；点击节点查看关联依据、正文和出处，再选择确认、排除或撤销关联。主题与标签支持编辑；没有足够分类线索的记录显示为“待归类”。图谱是已有记忆的视图，不是第五层或另一套事实主库。

已准备本地语义索引时，可点击节点的“查找可能相关”。建议仅供导航，按批有界扫描，每批最多显示 10 个候选；相似文本可能有不同主体、否定、数值或有效时间，长文本分块取最高相似度也可能误报。人工确认只表示两条记录有关，不表示内容相同。

**图谱辅助召回默认关闭。**手动开启后，仅从通过词面证据门槛的已选记录出发，在剩余预算内追加最多 3 条有效的人工确认关联；与既有来源关联共最多 5 条，不挤掉原本选中的证据。纯语义命中、共享主题和未经确认的语义建议不会自动扩散。人工排除的来源关联不再沿该边扩散。

人工关联也可能与本次问题无关或包含冲突信息，建议先在“回忆与整理”中模拟检查。在隔离合成预留集的 40 个图谱适用场景中，目标证据从 0/40 提高到 40/40，但该组难负例没有人工关联边。额外加入有确认关联的跨主体、跨时间难负例后，20/20 条被错误追加，新增项相关率为 40/60；标准、CPU、增强组合及两种常驻设置结果一致。因此不能据此默认开启，也不能将合成结果当作真实使用准确率。10,000 条规模下默认 L3 常驻的召回 P95 初测超过门槛；单独复测波动明显，随后三次均未达到门槛，不作为延迟保证。

## 设置与默认值

设置页内提供总览、分层记忆、记忆图谱、回忆与整理、私人日记，以及设置与迁移。大部分选项可直接修改：

| 项目 | 默认值 |
| --- | --- |
| 自动捕获用户陈述、普通记忆上下文注入 | 开启；仅规则识别到的内容进入长期层级 |
| L3 常驻 / 预算 | 全部当前有效 L3；独立额度 16,000 字节，计入总预算 |
| 普通检索 / 总预算 | 最多 30 条 / 48,000 UTF-8 字节估算，不是精确 token 数 |
| 深度整理 / 日期 | 本地规则；每天本机时间 03:00，空闲后执行。可切换工作区模型或 API |
| 图谱辅助召回 / 自动归档 | 关闭 / 关闭 |
| 场景上下文 / 场景外扩 | 仅显式加入的当前场景；只补充最多 5 条有界关联 |
| 备份 | 自动备份开启，默认**明文**普通记忆；每种保留 14 个恢复点 |
| 私人主会话 / 其他会话贡献 | 未绑定；贡献开关关闭 |
| 私人日记上下文 / 日记正文 | 8,000 字节预算 / Markdown 明文文件；需绑定主会话后才会读取 |
| 私人日记自动汇总 | 关闭；启用后按目标日期读取同工作区会话文本 |
| 私人作者白名单 | 空；默认没有外部插件可提交私人贡献 |

关闭“上下文注入”只停止自动注入，模型主动调用普通记忆工具仍可读取；如果不希望捕获、注入和使用记忆工具，应关闭插件的 `enabled`。L3 常驻不代表内容已经核实，过时记录应及时编辑或归档。

## 文件位置

每个 DSH 工作区使用同一套插件逻辑、各自的物理目录；不是在每个项目重复安装插件。`<DSH_HOME>\tidal-memory` 是共享系统根，用于模型、保护密钥、工作区位置登记、遗忘和私人隔离账本、恢复点，不再是已迁移工作区的活动记忆库。

```text
<DSH 工作区>\.tidal-memory\
    L0-buffer\buffer.sqlite3           短期普通缓冲
    L1-working\working.sqlite3         工作记忆
    L2-episodes\episodes.sqlite3       情景记忆
    L3-long-term\long-term.sqlite3     长期知识
    private\YYYY-MM-DD.md               每日唯一的私人日记正文，目录内只保留日期文件
    system\private\journal.sqlite3      私人日记元数据、版本和回执，不存正文
    system\private\transactions\        写入期间的暂存文件，不是日记阅读目录
    system\operations.sqlite3          运行状态和人工图谱修正
    indexes\topics.sqlite3             可重建的普通主题索引
    indexes\semantic.sqlite3           可重建的普通向量索引
    indexes\graph.sqlite3              可重建的普通图谱索引
<共享数据根>\
  models\                              本地模型与运行时，多个工作区共用
  system\workspace-locations\          本机文件夹归属与空间身份
  spaces\<旧空间键>\                   未映射的旧空间或恢复副本，不猜归属
  recovery\pre-workspace-…\            离线迁移时封存的原库，不再参与写入
  backups\<空间键>\                    自动和手动恢复点
  secrets\automatic-backup.dpapi        Windows 自动备份口令
  system\private-sessions.sqlite3      私人历史会话隔离登记，不含正文
  system\forget-ledger.sqlite3         同谱系遗忘标记，不含正文
```

1.0.1 的现有集中库必须在停写、备份和校验后迁移；不能将空目录冒充原来的记忆。完全退出 DSH 后，用宿主 Node 执行 `node scripts\migrate-workspaces.mjs --home "<DSH_HOME 绝对路径>"` 预览，确认路径后追加 `--apply`。脚本仅支持 rc.5 桌面的文件工作区登记；未映射的旧空间保留，不猜归属。工作区失效、只读、目录有其他所有者或 Git 已跟踪记忆文件时不会自动合并或覆盖。新目录自带忽略规则；不要强制提交它。Windows 目录限当前用户、SYSTEM 和管理员；这不是加密，也不防止同账户的其他工具访问。

L1–L3 的可读 `views` 也是派生文件；请在设置页修改主记录，不要通过编辑视图替代修改。图谱索引不保存第二份正文，向量和索引仍属于敏感派生数据。一个空间同时只允许一个写入者，其他写入进程会收到 `SPACE_BUSY`，不会抢锁或把空库伪装成成功。

## 隐私、备份与恢复

- **本地不等于与模型隔离**：规则、索引和 embedding 在本地运行；启用自动注入或调用记忆工具时，选中的普通记忆会随 DSH 的正常聊天请求发送给你配置的聊天模型。宿主会话日志及服务提供方的保留策略不由本插件控制。
- **模型整理是显式外发**：使用工作区模型或 API 整理时，当前空间有效普通 L1/L2 正文会发送给配置的服务；L0、私人日记及其他工作区不作为整理输入。API 密钥由 Windows DPAPI 保护，但模型服务对输入和输出的留存不受插件控制。
- **凭据与私人查询**：自动捕获会跳过符合常见凭据格式的消息，但格式识别不能保证发现所有秘密，请勿主动把凭据交给记忆。曾接收私人日记的会话不会将混合历史用于自动查询或发送给本地语义模型。
- **私人日记不是安全沙箱**：同一空间、同一本地日历日的获准作者贡献和自动摘要合并到 `private\YYYY-MM-DD.md`，SQLite 元数据和写入暂存分离到 `system\private`。旧 SQLite 正文、按年子目录和 `undated` 原件会迁移；导入日期优先取文件名、原件来源标记、日期元数据或首标题，不猜测正文中提及的事件日期。确无原日期时按导入日期归档，并明确标注“原日期未知”，不把归档日期当作事件日期。原始正文保持不变，迁移可恢复、可重试；遇到外部修改或冲突保留原件并报错。升级前请完整备份，迁移后不要直接降级到 0.8.0。默认不注入；只有绑定的精确主会话且 provider/model 匹配时，昨日及更早的日记片段才会按独立字节预算进入模型上下文。可选自动汇总会把所选日期的工作区用户与助手文本发送给已授权主会话模型；服务端保留策略不由插件控制。模型请求与宿主历史可能保留私人片段；fork、继承私人历史或路由不匹配的会话会被阻止，清空日记也不会解除已污染会话的限制。界面和普通工具不读取正文；Markdown 文件和事务暂存本身未静态加密，请配合磁盘加密和文件权限。
- **明文备份含敏感普通正文**：默认备份包含普通 L1–L3、修订、遗忘标记和人工图谱修正，不含 L0、私人日记、模型、派生索引或来源摘录。校验和只能发现损坏，不提供保密。深整理前即使关闭自动备份也会先创建恢复点。
- **可选加密**：设置页可选择加密普通记忆，或加密普通记忆与私人日记；使用 scrypt 与 AES-256-GCM。Windows 自动备份口令由当前账户 DPAPI 保护，保护失败不会回退明文。请离线保存原口令并演练恢复；忘记口令无法解密，换口令也不会更改旧备份。切换加密不会删除已有明文副本。
- **恢复与回退**：备份恢复到不存在的新空间，不覆盖当前空间。新版可读取 v1–v3 备份；v4 额外保存无正文的遗忘来源事件标记。旧版本不识别 v4 和新版遗忘账本，不能直接使用升级后的数据；回退前应保全新增数据和最新遗忘状态，在副本中核对后使用对应版本。
- **遗忘有边界**：已知来源事件及其派生记忆会一起屏蔽；旧标记缺少来源时标为覆盖未知，不能据此安全地重新读取旧历史。当前库和同数据根的同谱系恢复会协调已知标记，但无法远程改写旧离线备份、原文件、DSH 会话历史或外部服务记录，也不是磁盘法证级擦除。

旧文件仅在用户选择并预览后导入，不自动扫描或批量迁移。私人资料应单独选择私人导入；文件名识别不能保证识别所有私人内容，混合文件应先拆分。

## 进阶接口与验证

普通工具包括 `tidal_remember`、`tidal_recall`、`tidal_timeline`、`tidal_read_evidence`、`tidal_correct` 和默认关闭的 `tidal_find_history`。出处可按 ID 或主题分页读取；历史、归档和指定时点需显式选择。删除和私人清空只在管理页确认，不提供给模型自动执行。其他插件可通过宿主 `tidalMemory.forAgent(agent)` 获取受当前真实会话及工作区约束的接口，包括 `createScene`、`joinScene`、`setFocus`、`recordEvent` 和增量 `changes`；私人日记只提供受路由绑定的贡献与主会话回顾接口，不提供给任意会话全文读取。此服务为 future multi-bot 留出记忆契约，不创建、调度或监工会话。类型见 [1.0.3 的 `index.d.ts`](https://github.com/WJPGKZ/dsh-tidal-memory/blob/v1.0.3/index.d.ts)。

开发需要 Node.js 24 和 pnpm；测试与预览使用隔离合成数据，不读取用户记忆：

```powershell
pnpm install:host
pnpm check
pnpm test:unit
pnpm test:host
pnpm test:ui
pnpm bench:graph
```

本地模型准备完成后，可设置 `TIDAL_MODEL_ROOT` 并运行 `pnpm test:models`、`node scripts\evaluate-graph-semantic.mjs` 和 `node scripts\evaluate-graph-recall.mjs`。设置 `TIDAL_GRAPH_SPLIT=challenge` 可复现上述未通过的关联难负例；脚本会以失败退出码报告未达门槛。自动化宿主和浏览器检查不等同于真实桌面端的完整使用验收。历史变更见 [Releases](https://github.com/WJPGKZ/dsh-tidal-memory/releases)。
