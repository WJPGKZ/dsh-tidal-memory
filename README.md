# 潮汐记忆 · dsh-tidal-memory

为 **DeepSeek Harness 0.2.1-rc.5 / Node.js 24** 编写的四层外置记忆插件。提供 DSH 原生设置页面、跨会话共享、证据出处、自动记忆、可选人工确认与纠错、时间衰减、私人记录隔离和旧资料导入。

这是独立实现，不绑定旧人格、QQ 通道或旧插件私有协议。它不修改模型权重，也不声称复现真实神经网络。当前版本为 **0.3.0**；没有自动安装、扫描历史目录或迁移私人资料的行为。自动化 rc5 宿主与浏览器回归不等于真实桌面端完整交互验收。

## 工作区才是边界，不是会话

显式绑定一个工作区绝对路径和一个空间名，例如 `D:\Projects\example` → `example`。

- **同一工作区的所有原生会话共享 L0–L3**；会话 ID 只记录“哪次对话提供了证据”，不划分独立记忆库。
- 一个工作区只能绑定一个空间，一个空间只能绑定一个工作区。Windows 路径按大小写不敏感方式匹配；子目录不会自动继承绑定，符号链接别名不自动合并。
- 不同工作区不互相搜索。未绑定工作区和子代理默认不参与捕获、召回。
- 捕获、确定性规则整理、FTS5 检索和存储均在本地运行；不调用聊天模型整理，也不向整理模型发送会话片段。
- L1/L3 相同规范化文本和事实键合并出处，不重复创建记录。L2 额外按事件日期区分，避免把不同日期发生的事合并。这里是**确定性去重，不是语义同义改写去重**。
- 反复读到一条记忆、同一句话被多次复述，都不会自动提高其可信度或稳定性。

切换模型不会切换记忆库。删除会话也不会删除已经保存的工作区记忆。

## 四层如何配合

| 层 | 作用 | 写入与退出 |
| --- | --- | --- |
| L0 感知缓冲 | 短期保存用户消息，助手全文默认不捕获，可单独开启 | 不捕获思考链或工具输出，不新建 Markdown/修订全文副本，不进入新备份。已处理缓冲默认保留 72 小时；处理失败时保留并显示错误 |
| L1 工作记忆 | 当前任务、未完成事项 | 会话规则捕获的任务默认 24 小时到期归档，可设为 0 关闭；新用户证据可续期，仅自动到期归档的任务可自动恢复。手动完成、取消、归档不被重新激活；已有手工/工具记录不追溯添加期限 |
| L2 情景记忆 | 带时间和出处的陈述、经历、事件、历史资料 | 普通偏好/约定先以用户陈述自动可召回，重复跨日证据可巩固到 L3；保留事件日期与原始引用，不直接删除历史 |
| L3 长期知识 | 稳定偏好、约定、知识；可选的身份/自我条目 | 新记忆自动可召回，不自动初始化人格。同事实键的冲突例外进入复核，不能自动覆盖旧事实 |

每条普通记忆都有创建/更新时间、事件时间、状态、性质、版本、来源、派生关联和可选失效时间。L0 只展示当前版本，L1–L3 保留修订历史。**陈述、观察、推断、主观反思、历史资料分别标记，来源不是事实认证。**

主要流程：

```text
原生会话事件 → 工作区共享 L0
                  │
          本地确定性规则
                  │
        ┌─────────┴──────────┐
        │                    │
  自然陈述/任务/明确指令    指令期限不明确
  归类到 L1/L2/L3       L2，期限未指定
        │                    │
        └───────自动保存─────┘
                  ▼
       可召回记忆 → 相关性筛选 → 受预算限制的上下文
```

`记住：内容`、`请记住：内容`、`remember: content` 是明确的保存指令，但**不默认等于长期记忆**。“这次任务/本轮”归 L1，“昨天/上次”归 L2，“以后/长期/偏好”归 L3。期限无法判断时，作为带来源时间的用户陈述自动进入 L2，标记 `horizon: unspecified`，随情景记忆衰减，不当作永久约定。空指令不会生成记录，并显示诊断错误。

**没有“记住”前缀也能自动记忆，无需逐条审核**：这里的“自动”是符合本地规则的记录会直接保存并参与召回，**不是把每条普通对话全文永久保存**。默认开启 `autoCandidates`（保留配置键名称），从用户原文选择偏好、约定、决策、技术事实、纠正和经历；请求执行的事项及当前话题进入 L1，其余普通陈述先进入 L2。单片段最多 2000 字符，不再按前 8/32 条截断合格句子；仍受单条消息 16000 字符的捕获边界约束。记录规则名、来源事件、日期和摘录。示例、普通疑问、代码块、明显引用和“不用记”等内容保守跳过，但“请帮我检查……”等任务请求可保存。规则不总结隐含偏好、不做可靠语义理解、不把助手说法当作用户事实，也不自动覆盖被纠正的旧记录。**可召回不等于人工核实**；相关性门槛、失效时间、预算和隐私边界仍然生效。升级不重处理已处理的 L0，也不改写既有 L3。

规则词表是启发式，用户可在界面改层、有效范围和任务关联。`tidal_remember` 工具也自动保存，但始终标记为未核实推断，不能自行保护或确认。人工确认/强化是可选操作，不是进入召回的前置条件；重复捕获、读取和修订不会冒充新证据。重复写入合并来源时保留原状态，**不批量激活旧候选或导入资料**。同事实键冲突仍须处理，不静默覆盖。其他会话消息完成处理后默认 72 小时从当前 L0 清除；失败未处理及历史待复核记录不受此时限影响，停用期间也不会准时清除。

**本版本不包含模型整理入口，也不会因旧版 `autoExtract` 配置而调用模型。**开启上下文注入时，普通记忆会随正常聊天请求发送给配置的模型；关闭只停止自动注入，模型主动调用记忆工具的结果仍可进入聊天请求。若不希望使用任何记忆工具或注入，应关闭插件的 `enabled`。

## 召回、强化与“淡忘”

自动召回默认参考最近 **5 条用户消息**，逐条检索、按距离轻微降权，避免把上下文拼成一个长查询而稀释证据；重启恢复与实时消息使用相同窗口，不读取其他会话的窗口。每条检索线索最多 16000 个 UTF-16 代码单元，超长时保留首尾并修复 Unicode 边界。原始会话不被截断；超过 16000 字符的消息仍不写入 L0，并报告捕获上限。当前没有全文语义压缩，首尾之外的内容和较早话题仍可能漏召回。

召回用本地 SQLite FTS5 执行 AND、连续分词短语、OR 查询，每条线索、每种查询、每层最多 200 条，状态过滤在 SQL 限额前执行。索引覆盖整条记忆和标签，每条查询最多 64 个不同词项。排序结合全库文档频率、覆盖率与饱和式命中强度、区分度、时间和重要度，不再只依赖长查询覆盖比例。普通词面结果仍须通过 `minScore` 和 `bestScore × relativeFloor`；仅命中一个词时，其区分度至少为 0.5，常见功能词不算证据。**不会因为重要度高而随机补无关 L1/L2**。从合格证据出发，最多补充 5 条、两跳以内的明确 `parents` 来源关系，单独标注；这不是语义联想或共现推断，也不能绕过状态、有效期和隐私检查。

L3 默认采用 `residentMode=all`：有效且 active 的长期背景常驻，不需要用户每次重复关键词，**包含未核实推断和历史条目，常驻不等于事实已核实**。可改为 `core`（身份、偏好、约定及固定项）或 `pinned`。常驻不占普通检索条数，不再限制为总预算四分之一；默认独立额度 16000 字节，仍包含在总预算内。设为 0 可关闭常驻输出，但相关 L3 仍可通过普通检索返回。请先处理已过时的长期背景，不能依赖评分器判断事实是否仍成立。

人工确认与使用强化分开：宿主上下文/工具返回中有足够词面证据的条目，每个用户事件最多增加一次 `recallCount`，更新 `lastRecalledAt`，稳定度增加 0.1（上限 8）。纯常驻、来源关联和管理页模拟不会因此强化；重试幂等且支持写入中断恢复。使用强化不写 `reinforcedAt`、不变成人工确认、不改变证据性质，也不证明模型真的采用了该内容。

默认普通检索最多 **30 条、总预算 48000 字节**；可调到 100 条、192000 字节。预算按 UTF-8 字节保守计数，**不是准确 token 数，更不是 48000 tokens**。L3 常驻和最多 5 条来源关联不占 30 条名额，但共同服从总预算。候选、待复核、失效、已替代记录不自动注入；归档只能显式查询。诊断区分 `resident/query/association`，不记录私人正文。已有显式配置不被新默认值覆盖。

空闲“小整理”按游标逐批检查 200 条 L2，同文证据可跨批找到，不会一直停在第一批。每日深度整理默认在**本机时间 03:00**到期，宿主运行时每分钟检查；等待当前空间停止生成回复并达到 `idleMinutes`。关机/退出期间不运行；下次启动并空闲后补跑最近一次，包括凌晨 03:00 前补前一天，连续错过多天不连跑多次。定时按本地日期持久化去重，手动整理另行记录，不消耗当日定时名额。设置页显示最近一次（含手动）和下次应执行时间；尚未补跑时该时间可能在过去。

深整理处理全部待处理会话缓冲，再检查全部有效 L2，**不截在前 5000 条**。至少两个独立用户事件、两个 UTC 事件日期支持的稳定类别陈述才能提炼到 L3；保留原始 L2、全部出处与日期。不用 Jaccard 高相似度直接断言等义，仅规范化有限的已知同义词，保留语序、主语、限定语、数值和符号。规则可识别的否定/数值冲突及同事实键差异进入 review，并检查现有 L3；未解决的冲突不继续自动提炼。未知同义表达可能漏合并，不承诺通用语义理解或所有冲突都能检出。来源容量提高到每条 10000 个来源/关联与 16 MiB 来源信息；超限整组不发布，原文保留并报告，不静默截断证据。跨层操作可中断恢复，重复运行不重复提炼。

每次深整理前强制另存普通记忆恢复点，即使当天已有自动备份或 `autoBackup=false`；备份失败不开始整理。恢复点不含 L0、来源摘录或私人日记，私人日记不参与整理。可选自动归档只处理低重要度（不高于 0.5）、未固定、未强化且从未召回、在本库保存满八个半衰期的 L2，不删除；刚导入的古老资料有同样宽限。**自动归档默认关闭，优先保留可回忆内容而非节省磁盘。**这些是可解释的工程启发式，不是脑科学仿真。

旧文件导入按标题归组、合并连续段落，再以约 2–4 KB UTF-8 块切分；标题放在来源中，不在每块正文重复。分类决定新记录默认重要度（身份/约定 0.9、偏好 0.85、任务 0.7、知识 0.65、事件 0.5、观察 0.4），显式值保留。历史导入仍为候选，不自动固定或冒充当前事实。此改动**不会自动重写已经入库的旧切片或历史免责声明**；旧数据需单独、有备份地整理。私人文件仍单独分流，不生成普通摘要或普通召回。

检索完全本地，无云端 embedding、神经网络训练或向量数据库。小型本地 embedding 可作为未来的可选语义召回后端，但本版不下载、不运行，也不依赖它；向量只能辅助候选排序，不能判定事实真伪、期限或冲突。

## 数据位置

默认根目录为 **`<DSH_HOME>\tidal-memory`**，不是代码安装目录。设置页展示实际绝对路径。

```text
<dataRoot>\
  spaces\
    <space>\
      L0-buffer\
        buffer.sqlite3
        views\                  # 仅保留旧版清理入口，不新生成正文
      L1-working\
        working.sqlite3
        views\<id>.md
      L2-episodes\
        episodes.sqlite3
        views\<id>.md
      L3-long-term\
        long-term.sqlite3
        views\<id>.md
      private\
        journal.sqlite3
      system\
        owner.sqlite3
        operations.sqlite3
  backups\
    <space>\
      backup-<date>-<id>.json
```

**四层是四个独立 SQLite 数据库。** 私人记录另库，操作日志另库。`owner.sqlite3` 持有进程级写锁，第二个写入者会失败，不会抢锁。

SQLite 是唯一事实源，`views` 是方便定位和检查的生成视图。不要通过编辑生成 Markdown 修改记录；在 UI 保存后会重建视图。运行中会出现 SQLite 的 WAL/SHM 文件，不能只复制单个数据库文件当作可靠备份。

旧版潮汐记忆的分层数据库会在首次打开时原位补充保护/失效时间索引字段；现有记忆正文和元数据保留。FTS 分词索引单独记录版本：旧索引缺版本或不匹配时明确暂停关键词检索，设置页提供“重建搜索索引”。该操作从 SQLite 正文重建，每层在事务内提交；失败回滚当前层，已完成的层可安全重复重建。索引丢失或损坏时也可手动修复。此升级不导入其他插件、历史会话或私人文件。

升级前应停止写入并保留完整离线副本。层库结构升级后，不要直接用 `0.1.0` 打开同一目录；回退应使用升级前的副本或恢复到新空间，而不是降写数据库版本号。

空间按需打开，启动不再全量重写 Markdown，也不会仅因加载插件而创建 `default` 空间。日常维护通过状态/时间索引每类每层最多处理 500 条；积压需后续维护批次处理。L1–L3 可读视图仍在相关记忆变更时更新，丢失或写入失败时可手动重建。L0 新记录不生成视图；手动“重建可读文件”会删除带本插件原生成标记的旧 L0 副本，不删除手写文件。

并发仍是**单写者**，不是多进程共享事务。第二个进程占用时返回 `SPACE_BUSY`，只暂停对应空间，管理页显示未保存/未召回并允许重试，其他空间和 DSH 对话继续工作。不会抢锁、返回空库冒充成功或自动重放暂停期间消息；原文仍由 DSH 管理。SQLite 锁随进程退出释放，残留文件本身不是占用。安全的跨库只读快照降级尚未实现。

根目录通过插件配置 `dataRoot` 设置，留空使用默认路径。**不能在运行中直接切换目录。** 需要迁移时，停止插件、完整备份并复制整个根目录、修改插件配置后重启，再检查页面中的层级路径。不要让两个实例同时使用同一个空间。

## 私人日记的边界

管理页只显示数量、最近写入时间、占用、位置和允许的作者名称，**没有正文查看接口**。私人内容不进入普通搜索、工具召回、生成视图、诊断或明文备份，也不会自动升格成事实。

管理页首次打开时，如果只配置了一个工作区绑定，会自动选择该绑定的记忆空间，而不是停留在空的 `default`。多个绑定时仍由用户选择；进入页面后手动切换空间不会被刷新覆盖。召回错误按空间显示，后续成功召回会清除该空间已恢复的召回错误。

本插件负责私人记录的储存和权限，**第一版不自行生成“人格日记”，也不提供私人正文读取/反思接口**。后续“人味”插件可以申请写入能力；它必须是当前 Cordis 中真实登记、仍在运行且在白名单里的插件，不能只传一个作者字符串冒充。

这不是对本机管理员或同进程任意 JavaScript 插件的安全沙箱。SQLite 私人库在本机并未静态加密，任意文件工具也可能绕过界面访问它。需要更强保护时应结合磁盘加密、文件权限和受控工具授权。

## DSH 中的页面与默认值

设置中的 **潮汐记忆** 包含：

入口与「Prompt 管理」一样注册在 DSH 设置左侧，内容在原设置窗口内打开，不另起管理网站。页面只有内容布局和状态栏，**没有独立主题或明暗切换**；直接继承 DSH 的设置面板、文字、按钮和状态颜色变量，由现有 wallpaperengine 插件统一控制外观。

1. **总览**：四层数量、待处理状态、位置、维护入口。
2. **分层记忆**：搜索、新建、编辑、可选人工确认、性质和时间、出处与版本、跨层提炼、强化、级联删除。
3. **回忆与整理**：模拟召回、包含归档的查询、最近召回诊断。
4. **私人日记**：只看元数据、管理作者名单、明确确认后清空。
5. **设置与迁移**：工作区绑定、参数、旧资料预览导入、备份和恢复。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `enabled` | `true` | 捕获/召回开关；关闭后管理页仍可使用 |
| `bindings` | `[]` | 必须手动绑定工作区 |
| `tokenBudget` / `maxRecall` | `48000` / `30` | 总 UTF-8 字节预算 / 普通检索条数；常驻、来源关联另计条数 |
| `residentMode` / `residentBudget` | `all` / `16000` | L3 常驻范围和独立额度，仍受总预算约束 |
| `contextMessages` | `5` | 近期用户消息窗口，范围 1–10 |
| `minScore` / `relativeFloor` | `0.28` / `0.6` | 最低相关性分数、相对最高分门槛；不是事实可信度 |
| `autoConsolidate` / `dailyConsolidateAt` | `true` / `03:00` | 本地轻整理 / 每日深度整理时间（本机时区；留空关闭深整理） |
| `workingHours` | `24` | 后续会话规则生成的 L1 有效时长，范围 0–8760 小时，0 不自动到期；已有有效期不变 |
| `autoArchive` | `false` | 可选低使用旧 L2 归档；不删除 |
| `autoCandidates` | `true` | 自然陈述和当前任务自动保存并参与召回，无需逐条审核 |
| `captureAssistant` | `false` | 可选保存助手全文到短期 L0，不自动提炼助手说法 |
| `halfLifeDays` | `30` | 情景记忆基础半衰期 |
| `bufferHours` | `72` | 已处理 L0 保留小时数 |
| `idleMinutes` | `20` | 工作区空闲后执行本地缓冲整理的等待时间 |
| `injectContext` | `true` | 是否自动注入普通记忆；关闭不禁止模型主动调用记忆工具 |
| `autoBackup` / `backupKeep` | `true` / `14` | 自动备份 L1–L3 与恢复点保留数，不是保留天数 |
| `privateWriters` | `[]` | 私人作者插件白名单 |

用户消息到达时执行有界本地规则；后台每分钟检查一次，空闲时处理积压。同工作区正在生成回复时不运行后台整理。L0 原文仍是明文，不能把此插件当作可靠的自动秘密检测器；不要把凭据资料交给记忆。**72 小时仅适用于当前库的已处理 L0，不覆盖旧备份、外部副本、主动保存的 L1–L3 文本或 SQLite 底层未覆写页。**

## 安装与启用

本仓库不包含你的旧记忆、日记、凭据或宿主程序。**不要直接在真实 DSH 数据目录运行开发预览。**

1. 从 [GitHub 公共仓库](https://github.com/WJPGKZ/dsh-tidal-memory)取得代码，或在本地执行 `pnpm pack` 构建插件包。
2. 通过 rc5 桌面端的插件安装流程选择本地包；不同安装源的界面若不支持本地包，使用该安装源提供的 profile 包安装方式，不要手工覆盖内置宿主模块。GitHub 公共仓库并不代表已发布到 npm。
3. 包携带 `cordis.patch.yml`，入口 ID 固定为 **`tidal-memory`**。检查入口启用后，在设置中打开“潮汐记忆”。
4. 绑定一个真实工作区，确认“上下文注入”设置符合你的隐私预期，再用测试内容确认分层页面和跨会话共享，之后再导入旧资料。

本插件不截断或重写 DSH 会话历史，不接管 `billion-context` 的压缩工作；它通过 rc5 原生动态 runtime-context 提供记忆。`dsh-prompt-setting` 的 `complete: true` 约束提示词 section，不应据此推断动态上下文必然被移除；如果某个插件明确抑制 runtime context，潮汐记忆不会绕过该策略。建议在实际 agent preset 中验证最终行为。

此版本不包含自动模型整理，旧版后台整理开关会被忽略。自动注入和记忆工具结果仍使用 DSH 原有聊天模型路由；只关闭“上下文注入”不会禁止工具读取。

## 旧记忆重组与备份

导入支持 `.md`、`.markdown`、`.txt` 和包含 `memories` 数组的 fish-memory JSON（条目使用 `text`、可选 `at`、`id`）。只读取你在浏览器选中的文件，不自动遍历本机。

Markdown 按段落拆分，工具经验/偏好/约定等标题下的内容建议放 L3，其余先放 L2；保留原文、文件指纹和段落出处，日期不明确就标为未知，不伪造日期。先预览并取消不需要的条目，导入后都是历史候选，可在 UI 修改、拆分或跨层提炼，不会自动成为当前人格。

私人文件必须勾选“本批全部作为私人记录”，或使用可识别的 `private` / `私人` / `私密` 分隔文件名。**文件名识别不能保证发现所有旧日记**；含混合公开/私人段落的文件应先拆开。私人导入不会预览正文。凭据类文件名会被拒绝，但仍需自行检查内容。

每批最多 100 文件、10 MiB；每文件最多约 2 MiB；最多 3000 条普通候选。导入不是跨库大事务，发生故障时已写入的部分可能保留，重复执行会按确定性键合并。旧原件不会被改动或删除。

- **明文备份**：只含 L1–L3 正文、其版本历史和遗忘标记；不含 L0 及来源对象中的 `excerpt`。保留来源 ID/事件信息，但恢复后不能从备份恢复被排除的原始摘录。记忆正文仍可能包含用户主动保存或规则选取的会话片段，不是匿名数据。校验和用于发现损坏，不代表来源可信。
- **加密备份**：同样排除 L0 和来源摘录；填写至少 12 字符口令后另包含私人记录，使用 scrypt 和 AES-256-GCM。口令不写入配置，丢失后无法解密。
- **自动备份**：普通后台维护在 L1–L3 状态变化后最多每天生成一次；每次深整理额外生成整理前快照。合计保留最近 14 个恢复点（可调），不保证 14 天；同日按实际写入时间保留，不按随机文件名取舍。
- **旧副本风险**：早期明文备份含 L0 原文，旧 L0 视图也可能存在。新版不会擅自删除备份；72 小时 TTL 不会追溯删除这些副本。升级后应检查旧备份，并在需要时手动清理或加密；视图清理入口只处理本插件的生成文件。
- **恢复**：必须恢复到一个不存在的新空间，校验完成后才发布；不会覆盖当前空间。然后解除旧绑定并绑定恢复空间。UI 请求上限 12 MiB，超过时需离线分批迁移。
- **遗忘**：删除当前库中的记录、派生记录、版本和生成视图，记录文本摘要防止原内容被重新导入；不是同义内容检测，也不是磁盘法证级擦除。旧备份、原文件和 DSH 会话历史不受影响，从旧备份恢复仍可能重新带回旧内容。

## 给后续插件的接口

宿主服务名称为 `tidalMemory`，契约版本 `1`；类型见 `index.d.ts`。

```js
export const name = 'example-memory-writer';
export const inject = ['tidalMemory'];

export function apply(ctx) {
  // 在获准的插件事件中使用宿主登记的 agent：
  // ctx.tidalMemory.forAgent(agent).proposeMemory({
  //   layer: 'L1', text: '尚未完成的工作', category: 'task'
  // });
  // ctx.tidalMemory.forAgent(agent).recall('工作关键词');

  const writer = ctx.tidalMemory.privateWriter(ctx);
  // 仅在插件完成启动且作者被用户允许之后调用：
  // writer.append('example', '作者插件自己的私人记录', []);
}
```

`forAgent` 验证宿主登记身份并通过工作区选择空间，不接受任意会话字符串作为普通插件读写授权。`proposeMemory` 保留接口名称，但新记录默认自动可召回，性质强制为推断；不能自行确认或保护。`tidal_correct` 只允许修改未人工确认、未保护且所有来源均为工具提议的记录，保留修改会话和版本。手工改正或合并了用户原话的记录不能再由工具改写。私人作者只能写入，不能读取现有日记。此版本没有 `submitEvent`、人格演化、情绪系统、自动技能生成或 QQ 适配层。

提供给模型的工具恰好四个：

| 工具 | 功能 |
| --- | --- |
| `tidal_remember` | 自动保存工作区共享记忆，标为未核实推断 |
| `tidal_recall` | 检索普通有效记忆，可显式包含归档 |
| `tidal_read_evidence` | 读取普通记录的来源集合 |
| `tidal_correct` | 修订未确认、未保护的工具推断，不能改用户原话或手工记录 |

**不向模型提供 `tidal_forget`**。删除和私人清空只能在管理页明确确认。

使用 Node.js 24，命令在本仓库运行：

```powershell
pnpm install
pnpm install:host
pnpm check
pnpm test
pnpm test:host
pnpm test:ui
```

`pnpm-workspace.yaml` 关闭自动安装可选宿主 peer，避免把整套 DSH 装入开发目录；只允许 esbuild 的安装脚本。生产端使用宿主模块和 React，不打包第二份 DSH/React。`node:sqlite` 需要 Node 24。

`tests/host-fixture` 使用独立清单和锁文件安装公开 npm 的精确 rc5 模块，不依赖本机 DSH 安装。`pnpm test:host` 缺依赖或版本不符时失败，不再默认 skip；`pnpm test` 也包含这些检查。仅运行核心逻辑可用 `pnpm test:unit`。CI 在 Windows/Node 24 上安装锁定依赖并强制执行宿主检查；加入工作流不代表已运行远端 CI，也不等于设置了分支保护。

宿主检查分别覆盖 Cordis 生命周期和真实 `dsh-agent-loop` 的最终请求构造：普通提示词、`complete` 提示词、显式 `suppressRuntimeContext()`、关闭插件注入。使用真实 session/projection/tools 服务和假模型传输，验证到宿主传输入口收到的消息，不发真实 API 请求，不声称覆盖网络供应商、压缩器或 200 轮任务连续性。宿主明确抑制运行时上下文时，普通记忆不会绕过该开关。

`preview` 只监听 `127.0.0.1:4319`，使用临时合成数据，不连接真实 DSH、不调用模型。退出时清理临时目录。浏览器检查优先使用本机 Edge/Chrome，也可设置 `TIDAL_BROWSER` 为浏览器可执行文件绝对路径；没有浏览器时可执行 `pnpm exec playwright install chromium`。

核心检查覆盖分层持久化、工作区隔离、跨会话合并、版本冲突、恢复、遗忘、隐私排除和后台生命周期。浏览器检查使用实际 `client.js`，而不是另一份展示页面。

可通过 `TIDAL_HOST_MODULES` 指向独立的宿主依赖目录进行对照；测试仍会检查清单中的全部精确版本，缺少模块不会跳过。不要提交宿主副本，默认使用锁定的公开 npm 夹具。

独立契约与浏览器检查不等于已在你的 DSH 桌面会话中安装验证。真实安装、旧资料取舍和迁移应在备份后单独完成。

### 可复现的合成基准

`pnpm bench 10000` 使用 `tests/fixtures/recall.mjs` 的标注语料，分别在独立 Node 进程运行原始 `0.1.0` 提交 `e389bcd6adbb4a4c3a93efb386f089edfd08bd2a` 与当前工作树。可在记录数后传入另一基线 git ref。需要本地 git 历史，不联网拉取代码，不读取真实记忆；临时数据库退出时清理，详细结果保存在 `.preview/benchmark.json`。

28 个查询分为 15 个词面探针、10 个无关/过于宽泛探针和 3 个纯改写探针。初始化批量入库只用于装载夹具，不计为业务写入速度；原始捕获延迟另外采样 20 次。召回先预热一轮，再采样 56 次；启动只测一次，维护测 5 次。`precisionReturned` 的分母是实际返回条数，不是固定 6，空结果按 0 计。

这是开发夹具而非独立测试集。为单独测量词面召回，基准固定 `residentMode=pinned`、`maxRecall=6`，**不是默认的全部 L3 常驻和 30 条检索配置**。因此不能据此推导默认常驻策略的精确率、真实使用准确率或与 fish-memory 的排名。候选提取、混合隐私文本、跨语种和语义改写仍需要更多独立标注。基准不表示真实桌面安装或从旧库迁移已经验收。

| 指标 | 0.2.0 基线 `39c7f3e` | 0.2.1 工作树 |
| --- | --- | --- |
| 重开空间耗时（一次） | 30.9 ms | 25.6 ms |
| 原始 L0 捕获 P95（20 次，不含运行时分类） | 1.50 ms | 1.58 ms |

| 词面探针命中 | 15/15 | 15/15 |
